# 实验协议和参数口径

本表是横向比较前的协议账本。若某字段写作 `config-declared`，以对应 YAML 或 manifest 中的字段为准；报告时仍需要把实际 resolved config、commit、split metadata 和输出路径补入 [result_claims_registry.md](result_claims_registry.md)。

状态分类：

- `formal`：可作为当前正式协议运行。
- `lowmem`：正式协议的资源受限变体，必须保留 paper approximation caveat。
- `smoke` / `mock`：只验证代码路径、schema 或 forward，不用于论文或正式结果比较。
- `debug`：用于继承、clone parity 或变量隔离，不作为最终 sweep 结论。
- `evaluation-only` / `diagnostic-only`：只读已有 config/checkpoint/manifest 或导出诊断产物。
- `upper-bound`：使用 test split 选 checkpoint 或 oracle 信息，只用于上界诊断。
- `historical ablation`：保留历史证据，不覆盖当前推荐口径。

## 输出边界

上述协议只允许把真实数据、cache、metrics、figures、TensorBoard event 和 checkpoint 写入 ignored 的 `dataset/`、`outputs/`、`outputs/cache/`、`logs/` 或显式本地 artifact 目录。源码变更只记录摘要、路径和 caveat，不提交运行产物。
