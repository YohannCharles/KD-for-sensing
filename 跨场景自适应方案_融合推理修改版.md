# 跨场景自适应波束预测方案（修改版）

> 版本：**Radio-Semantic Shared-Private Target Adaptation**
>
> 用途：在你现有已经部分实现的 shared/private + target adapter 代码基础上，做**最小侵入式修改**，把原来的“coarse beam prototype”快速验证版升级为“propagation-aware / radio-semantic prototype”快速验证版。
>
> 核心变化：不再只让 shared branch 学 `beam // K0` 这种粗 beam index，而是让 shared branch 学更通用的**无线传播语义**，例如 beam-power profile 的主峰位置、能量扩散程度、多径/宽峰形态。private branch 仍然负责 scene/town/weather-specific fine correction，target 阶段通过小 adapter 修正私有分支。

---

## 0. 为什么要改

原始方案是：

```text
多模态输入 -> fusion -> h
h -> shared c -> coarse beam group
h -> private s -> scene-specific refinement
[c, s] -> fine beam prediction
target: s' = A_t(s)
```

这个方案可以验证 shared/private 是否有用，但 `coarse group = beam // K0` 的物理含义仍然偏弱。它只表示“最优 beam 大概在哪个方向”，没有显式区分：

```text
1. 单峰强 LOS 型；
2. 相邻 beam 都强的宽峰型；
3. 多个候选 beam 都不弱的多径反射型；
4. 主峰不稳定、能量分散型。
```

修改后，shared branch 不再只学 `coarse beam group`，而是学习：

```text
radio-semantic label r
```

它由 beam-power profile 或 CSI/codebook 派生，表示更通用的传播形态。这样 source prototypes 不再只是 `mu_g`，而是：

```text
mu_r: 第 r 类无线传播语义在 shared feature c 空间中的原型中心
```

private branch 则继续学习：

```text
scene / town / weather / local geometry / target-specific fine correction
```

最终推理不是“prototype 直接输出 beam”，而是：

```text
shared c：提供通用传播语义
private s'：提供目标场景修正
radio assignment alpha：提供传播语义条件
beam head：融合 [c, s', e_alpha] 输出最终 64-beam 概率
```

## 1. 项目目标

请在现有多模态 beam prediction 框架上实现快速验证版本：

```text

```

快速验证目标不是完整投稿系统，而是在 2–4 周内验证下面假设：

> 在 Multimodal-Wireless 跨场景 / 跨 town / 跨 weather 波束预测中，比起只用 coarse beam group prototype，让 shared branch 学习由 beam-power profile 派生的 radio-semantic prototype，是否能更稳定地跨场景迁移；target 阶段是否只需要更新 private adapter 和少量预测头参数，就能恢复 target-specific fine beam mapping。


其中 **V6 是新的 full method 快速版**。

## 2. 数据集与任务设定

### 2.1 主数据集

主数据集改为：

```text
Multimodal-Wireless
```

原因：

```text
1. 它同时包含 sensing modalities 和 wireless communication channel；
2. 它基于 CARLA + Sionna pipeline，适合从 CSI / codebook 计算 beam-power profile；
3. 它有 virtual town、communication scenario、weather 等天然 domain 变量；
4. 它比 DeepSense6G 更适合做 propagation-aware / radio-semantic supervision。
```

### 2.2 不要把 channel / CSI 当作输入模态

模型输入仍然是 sensing modalities：

```text
camera / radar / GPS / LiDAR / IMU
```

快速验证阶段建议先用：

```text
camera + radar + GPS
```

channel / CSI / beam_power 只用于：

```text
1. 构造 source 训练标签；
2. 构造 source radio-semantic label；
3. 计算评价指标；
4. few-shot target 阶段有限标注监督。
```

在 **label_budget = 0 的 target adaptation 阶段**，严禁使用 target 的真实：

```text
beam label
CSI
beam_power
q_power
radio_semantic_label
```

否则就是 target leakage。

根据 Multimodal-Wireless 实际 metadata 字段实现以下 split。若某些 metadata 字段名称不同，请 Codex 先做 dataset inspection，不要假设固定文件结构。

### 3.1 Leave-One-Scenario-Out



`target_adapt` 用于 target adaptation，`target_test` 只用于最终测试。

### 3.5 Few-shot label budget


采样策略优先级：

```text
1. radio-semantic-label stratified sampling；
2. coarse-group stratified sampling；
```

## 5. Radio-semantic label 构造

新增模块：

```text
datasets/radio_semantic_label.py
```

或：

```text
utils/radio_semantics.py
```

实现类：

```python
class RadioSemanticLabelBuilder:
    def __init__(
        self,
        num_beams=64,
        group_size=8,
        mode="peak_spread",
        num_spread_bins=3,
        entropy_bins=None,
        kmeans_path=None,
        eps=1e-8,
    ):
        ...
```

### 5.1 模式 A：coarse fallback

保留旧版：

```python
g = best_beam // group_size
r = g
```

这用于 ablation，不是最终主方法。

### 5.2 模式 B：peak_spread，推荐快速主方法

输入：

```python
beam_power: Tensor[64]
```

步骤：

```python
P = normalize_power(beam_power)
best_beam = argmax(P)
peak_group = best_beam // group_size
```

计算 spread。建议实现两个可选指标：

#### 方案 1：top-k mass

```python
sorted_P = sort(P, descending=True)
top1 = sorted_P[0]
top3_mass = sorted_P[:3].sum()
top8_mass = sorted_P[:8].sum()
```

直觉：

```text
top1 占比越高，越像窄峰；
top8_mass 分散但仍集中，可能是宽峰；
如果多个远距离 beam 都不弱，可能是多径。
```

#### 方案 2：entropy

```python
q = P / P.sum()
H = -sum(q * log(q + eps)) / log(num_beams)
```

再把 \(H\) 分成：

```text
spread_bin = 0: narrow / single-peak
spread_bin = 1: medium-spread
spread_bin = 2: wide / multi-peak
```

推荐快速版使用 entropy：

```python
if H < 0.35:
    spread_bin = 0
elif H < 0.65:
    spread_bin = 1
else:
    spread_bin = 2
```

最终：

```python
r = peak_group * num_spread_bins + spread_bin
num_radio_classes = num_groups * num_spread_bins
```

若：

```text
num_beams = 64
group_size = 8
num_groups = 8
num_spread_bins = 3
```

则：

```text
num_radio_classes = 24
```

### 5.3 模式 C：kmeans_power，后续增强

对 source train 的 normalized beam-power profiles 做 KMeans：

```text
input: normalized beam_power vector [64]
num_clusters: 16 / 24 / 32
```

得到：

```text
radio_semantic_label = cluster_id
```

该模式更灵活，但快速验证阶段不建议优先做。

## 6. 模型结构修改

### 6.1 总体结构

仍然采用：

```text
multimodal encoders -> token fusion -> h -> shared/private split
```

```python
h = Fusion({z_camera, z_radar, z_gps, ...})
c = Ec(h)  # shared representation
s = Es(h)  # private representation
```

维度建议保持原方案：

```text
h: 256
c: 128
s: 64
```

### 6.2 Shared branch

shared branch 不再只学习 coarse group，而是学习 radio-semantic pattern：

```python
radio_logits = radio_head(c)  # [B, R]
```

其中：

```text
R = num_radio_classes
```

如果保留 hierarchical beam baseline，也可以继续输出：

```python
coarse_logits = coarse_head(c)  # [B, G]
```

但 full method 的主监督应是：

```text
radio_semantic_label
```

而不是仅仅 `beam // K0`。

### 6.3 Private branch

private branch 保持：

```python
s = Es(h)
```

target 阶段：

```python
s_adapt = A_t(s)
```

source 阶段：

```python
s_star = s
```

target 阶段：

```python
s_star = s_adapt
```

private branch 接 scene/town/weather/domain classifier：

```python
scene_logits_s = scene_classifier_s(s)
```

目的是让 private branch 保留 target-specific / scene-specific 信息。

### 6.4 Shared scene confusion

对 shared branch 继续使用 GRL：

```python
scene_logits_c = scene_classifier_c(GRL(c))
```

目的是让 \(c\) 尽量减少 scene/town/weather/domain 信息。

### 6.5 Beam prediction head：关键修改

原方案中：

```text
coarse head: p(g | c)
fine head: p(delta | c, s, g)
p(b) = p(g) p(delta | g)
```

这适合 coarse group，因为 \(g\) 是 beam index 的父类。

但 radio-semantic label \(r\) 不是 beam index 的严格父类，它包含 spread / multi-path 信息，不能简单写成：

```text
p(b) = p(r) p(delta | r)
```

因此新的 full method 使用下面的融合推理方式。

### 6.6 最小实现版：不把 alpha 显式送入 beam head

```python
beam_logits = beam_head(torch.cat([c, s_star], dim=-1))  # [B, 64]
```

同时保留：

```python
radio_logits = radio_head(c)
```

radio prototype 只用于：

```text
1. source 训练的 radio semantic auxiliary loss；
2. target adaptation 的 prototype assignment / consistency。
```

这是最稳的第一版。

### 6.7 增强实现版：把 radio assignment 条件送入 beam head

新增 embedding table：

```python
radio_embedding = nn.Embedding(num_radio_classes, radio_embed_dim)
```

source 训练时可以用两种方式：

#### hard label embedding

```python
e_r = radio_embedding(r_true)
```

#### soft predicted embedding

```python
alpha = softmax(radio_logits / tau)
e_alpha = alpha @ radio_embedding.weight
```

target 推理时不能用真实 r，只能用 source prototype assignment：

```python
alpha = softmax(cosine(c, mu_radio_c) / tau)
e_alpha = alpha @ radio_embedding.weight
```

最终 beam head：

```python
beam_logits = beam_head(torch.cat([c, s_star, e_alpha], dim=-1))
```

推荐配置：

```yaml
model:
  use_radio_condition_in_beam_head: true
  radio_embed_dim: 32
```

如果实现压力大，先设为 false，后面再做消融。

## 7. Target adapter 与最终推理流程

### 7.1 Adapter

保留 bottleneck residual adapter：

```python
class BottleneckAdapter(nn.Module):
    def __init__(self, dim=64, rank=16):
        super().__init__()
        self.down = nn.Linear(dim, rank)
        self.up = nn.Linear(rank, dim)
        self.act = nn.GELU()
        nn.init.zeros_(self.up.weight)
        nn.init.zeros_(self.up.bias)

    def forward(self, s):
        return s + self.up(self.act(self.down(s)))
```

### 7.2 Source 阶段推理

```text
x -> h -> c, s
radio_logits = radio_head(c)
alpha = softmax(radio_logits)
e_alpha = alpha @ radio_embedding.weight   # 如果启用
beam_logits = beam_head([c, s, e_alpha])
pred_beam = argmax(beam_logits)
```

### 7.3 Target adaptation 阶段推理

```text
x_t -> h_t -> c_t, s_t
s'_t = A_t(s_t)

alpha_t = softmax(cosine(c_t, mu_radio_c) / tau)
e_alpha_t = alpha_t @ radio_embedding.weight   # 如果启用

beam_logits = beam_head([c_t, s'_t, e_alpha_t])
pred_beam = argmax(beam_logits)
```

### 7.4 最终测试阶段

最终测试阶段和 target adaptation 阶段一致，但不更新参数：

```text
x_test -> h -> c, s -> s' -> alpha -> e_alpha -> beam_logits -> pred_beam
```

### 7.5 不要让 prototype 直接预测 beam

错误做法：

```text
find nearest mu_r -> map r to beam
```

正确做法：

```text
prototype 只提供 radio-semantic condition / alignment anchor；
最终 beam 仍由 BeamHead([c, s', e_alpha]) 输出。
```

## 8. Source prototypes

source pretraining 后，对 source train set forward 一遍，保存：

```python
{
    "mu_radio_c": Tensor[R, shared_dim],
    "count_radio": Tensor[R],

    "mu_coarse_c": Optional[Tensor[G, shared_dim]],
    "count_coarse": Optional[Tensor[G]],

    "config": {...}
}
```

### 8.1 只建议保存 shared prototype

旧方案中可能保存：

```python
rho_s = source private prototype
```

新方案建议不要把 source private prototype 作为 target private 的强对齐对象。

原因：

```text
private branch 本来就是场景私有的；
source private 和 target private 不应该被强行对齐；
target private 应该通过 target-private prototype bank nu_r 自己形成目标场景修正中心。
```

如需兼容旧代码，可以保留 `rho_s`，但默认不使用。

## 9. Target-private prototypes

target adaptation 初始化：

```python
nu_radio_s = zeros[R, private_dim]
nu_count = zeros[R]
```

对 target batch：

```python
c = Ec(h)
s = Es(h)
s_adapt = Adapter(s)

alpha = softmax(cosine(c, mu_radio_c) / tau)
r_hat = argmax(alpha)
conf = max(alpha)
```

如果：

```python
conf > confidence_threshold
```

则用 EMA 更新：

```python
nu_radio_s[r_hat] = m * nu_radio_s[r_hat] + (1 - m) * normalize(s_adapt)
```

当某个 `nu_radio_s[r]` 还没有被初始化时，可以用第一个高置信样本初始化。

### 9.1 Target-private prototype loss

当 `nu_radio_s[r_hat]` 已初始化，并且通过 warmup 后：

```python
L_proto_private = || normalize(s_adapt) - stopgrad(nu_radio_s[r_hat]) ||_2^2
```

注意：

```text
这个 loss 是让 target private features 在 target 内部稳定聚类；
不是强行贴 source private prototypes。
```

### 9.2 Shared prototype assignment loss

可以选做：

```python
L_proto_shared = sum_r alpha_r * || normalize(c) - mu_radio_c[r] ||_2^2
```

但由于 target adaptation 时 `Ec` 默认冻结，这个 loss 主要影响很小。快速版可以不加，或只用于监控。

## 10. Loss 设计

### 10.1 Source training loss

```text
L_source =
  L_beam
+ lambda_radio * L_radio
+ lambda_orth * L_orth
+ lambda_scene_c * L_scene_c
+ lambda_scene_s * L_scene_s
+ lambda_power * L_power_optional
```

### 10.2 Beam prediction loss

快速版建议直接使用 flat 64-beam CE：

```python
L_beam = CE(beam_logits, beam_true)
```

如果保留旧 hierarchical head，也可以：

```python
L_beam = L_hier + lambda_flat * L_flat
```

但 full method 中要注意：

```text
radio_semantic_label 不是 hierarchical beam parent；
不要写成 p(b)=p(r)p(delta|r)。
```

### 10.3 Radio semantic loss

```python
L_radio = CE(radio_logits, radio_semantic_label)
```

仅当 batch 中有 `radio_semantic_label` 时启用。

### 10.4 Optional power-profile loss

如果 beam_power 可靠，可以增加：

```python
q_power = softmax(beam_power / power_temperature)
pred_power_dist = softmax(power_head(c))
L_power = KL(q_power || pred_power_dist)
```

快速验证阶段建议先关闭：

```yaml
loss:
  use_power_profile_loss: false
```

因为它更容易引入训练不稳定和 target leakage 风险。

### 10.5 Decoupling losses

保留：

```python
L_orth
L_scene_c = CE(scene_classifier_c(GRL(c)), domain_id)
L_scene_s = CE(scene_classifier_s(s), domain_id)
```

其中 `domain_id` 可以来自：

```text
scenario / town / weather / combined_domain
```

建议优先用：

```text
combined_domain = scenario_id
```

如果做 town split，再额外记录 town label。

## 11. Target adaptation loss

### 11.1 Few-shot supervised target

当 label_budget > 0：

```text
L_sup = CE(beam_logits_labeled, beam_true)
```

如果 labeled target 有 beam_power，也可以构造 radio_semantic_label，但只允许在 labeled subset 上用：

```text
L_radio_labeled = CE(radio_logits_labeled, radio_semantic_label_labeled)
```

推荐快速版先只用 beam CE，避免监督过强。

### 11.2 Unlabeled target

当 label_budget = 0：

```text
L_unsup =
  lambda_ent * L_entropy
+ lambda_cons * L_consistency
+ lambda_proto_private * L_proto_private
```

其中：

```python
L_entropy = -sum(p_beam * log(p_beam))
```

consistency 可选：

```text
weak augmentation prediction 和 strong augmentation prediction 保持一致
```

快速版可以先只做 entropy + private prototype loss。

### 11.3 Semi-supervised target

当 label_budget > 0 且仍使用 unlabeled target_adapt：

```text
L_target = L_sup + lambda_unsup * L_unsup
```

## 14. 指标

必须实现：

```text
Top-1
Top-3
Top-5
coarse beam accuracy
radio-semantic accuracy
normalized received power
beam power loss dB
trainable parameter ratio
adaptation time
```

### 14.1 normalized received power

如果有 beam_power：

```python
NRP = P[pred_beam] / (P[best_beam] + eps)
```

### 14.2 beam power loss

```python
loss_db = 10 * log10((P[best_beam] + eps) / (P[pred_beam] + eps))
```

### 14.3 radio-semantic accuracy

仅在 source val / target test evaluation 中计算，用于分析，不用于 label_budget=0 target adaptation 训练：

```python
radio_acc = mean(argmax(radio_logits) == radio_semantic_label)
```

注意：

```text
target test 可以计算 radio_acc，因为这是离线评价；
target adaptation 不能用 target radio_semantic_label 训练。
```

## 15. 最重要的消融

### 15.1 coarse prototype vs radio-semantic prototype

这是新方案最关键的消融：

```text
V5 Adapter + coarse prototype
V6 Adapter + radio-semantic prototype
```

```text

- fusion；

2. private branch 学 scene/town/weather/domain-specific fine correction；
3. source 训练后在 shared feature c 空间保存 source radio-semantic prototypes mu_radio_c；
4. target adaptation 阶段冻结 encoders/fusion/Ec/Es，只更新 private adapter、beam head 最后一层和 target-private prototype bank；
5. 最终推理时融合 c、target-adapted private feature s'、以及可选 radio assignment embedding e_alpha 输出 64-beam logits；
6. prototype 不直接输出 beam，只提供 semantic anchor / condition；
7. label_budget=0 的 target adaptation 阶段严禁读取 target 的真实 beam、CSI、beam_power、q_power、radio_semantic_label 作为监督。

请按以下优先级实现。

P0：Dataset inspection and compatibility
- 新增 scripts/inspect_dataset.py，打印 Multimodal-Wireless 数据根目录下的文件结构、metadata keys、可用 modalities、是否有 CSI/channel/beam_power/beam label。
- 新增 datasets/multimodal_wireless_dataset.py。
- Dataset __getitem__ 返回：
  camera/radar/gps/lidar/imu optional tensors,
  beam optional,
  beam_power optional,
  radio_semantic_label optional,
  scenario/town/weather/domain,
  sample_id。
- 如果实际数据字段名不同，请使用配置项映射，不要写死。

P1：RadioSemanticLabelBuilder
- 新增 RadioSemanticLabelBuilder。
- 支持 mode = coarse / peak_spread / kmeans_power。
- peak_spread 模式：
  best_beam = argmax(beam_power)
  peak_group = best_beam // group_size
  normalized entropy H = -sum(q log q) / log(num_beams)
  spread_bin 根据 thresholds [0.35, 0.65] 分成 0/1/2
  radio_semantic_label = peak_group * num_spread_bins + spread_bin
- 如果没有 beam_power，退回 coarse mode，并在日志中 warning。

P2：Model changes
- 在 hist_beam.py 中增加 radio_head(c) -> radio_logits [B, R]。
- 增加可选 radio_embedding table。
- BeamHead 支持两种输入：
  1) concat(c, s_star)
  2) concat(c, s_star, e_alpha)
- source 阶段 s_star=s。
- target 阶段 s_star=adapter(s)。
- 如果 use_radio_condition_in_beam_head=true：
  source 阶段 e_alpha = softmax(radio_logits) @ radio_embedding.weight；
  target 阶段 e_alpha = softmax(cosine(c, mu_radio_c)/tau) @ radio_embedding.weight。

P3：Loss changes
- source loss:
```

## 19. 成功判据

  

这套修改值得继续做的最低标准：

  

```text

1. V6 radio-semantic prototype 在跨 town / 跨 scenario / 跨 weather 上优于 V5 coarse prototype；

2. V6 在 label_budget=0 时相比 source-only 有提升；

3. V6 在 5/10 labels 下相比 adapter-only 更稳；

4. V6 接近 Full FT，但 trainable params < 2%；

5. V6-b [c, s', e_alpha] 优于 V6-a [c, s']，说明 radio assignment 不只是训练辅助，也能作为推理条件。

```

  

如果 V6 不优于 V5，则说明 `radio_semantic_label` 构造可能不合适，需要调整：

  

```text

1. spread_bin 阈值；

2. KMeans over beam-power profile；

3. peak_group + top-k mass；

4. LOS/NLOS / path count / delay spread 等 path-level 标签。

```

  

如果 V6-b 不优于 V6-a，不代表方法失败，只说明 prototype 更适合做 adaptation anchor，而不是显式推理条件。
